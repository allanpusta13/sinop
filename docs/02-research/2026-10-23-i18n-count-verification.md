## 1. Counting rule (as implemented)

The rule is not invented here — it is the rule `tests/Unit/Lang/TranslationKeyParityTest.php`
already enforces. It is reproduced verbatim by `docs/02-research/i18n-count-reproduction.php`.

**Source files.** `lang/<locale>/*.php`, one file per namespace. The canonical namespace
list is derived from `lang/en/`, and locales are enumerated by scanning `lang/` for
subdirectories (this project has no `available_locales` config key).

**What counts as an entry.** Each file is `require`d and recursively flattened to
dot-notation. A *translation entry* is one leaf scalar:

```
'fields' => ['name' => 'Product name']   →   one entry:  resources.products.fields.name
```

Intermediate arrays are **not** entries. Namespaces empty on both sides (`return []`) are
skipped as intentionally-empty structural placeholders.

**What counts as a placeholder.** Not a structural property — a *textual tag*. An entry is
a placeholder when its line carries the marker

```
// TODO(i18n): translate
```

counted with `mb_substr_count(file_get_contents($file), '// TODO(i18n): translate')`.
The English text stands in for a real translation and is counted, but does **not** fail
parity. Content completeness is a separate workstream.

**What counts as an orphan.** A key present in a non-canonical locale's flattened set but
absent from the canonical `lang/en` flattened set for the same namespace.

**Counted / excluded, explicitly:**

| Counted | Excluded |
|---|---|
| Leaf scalars (string/int) in `lang/<locale>/*.php` | Intermediate array nodes |
| Namespaces present on **both** sides | Namespaces empty in `lang/en` **and** the locale (`` `return []` ``) |
| The literal marker `// TODO(i18n): translate` | Any other comment, and the marker inside a string value |
| `vendor/`, `storage/`, `node_modules/` | never scanned — counts come from `lang/` only |

**Source files.** The counts are derived solely from `lang/en/*.php`, `lang/es/*.php`, and
`lang/tl/*.php` — 19 namespace files per locale (57 files total). No other directory
contributes to any figure in this document.

## 4. What the placeholders are

`lang/es` and `lang/tl` each hold **1253** flattened entries. 1253 − 258 orphans = **995**
= the canonical `en` count exactly. Structural parity therefore holds: every locale's key
set is `en`'s key set plus a 258-key orphan block. No missing keys in either locale.

## 5. Why the issue figures are stale

The `860` and `847` figures both trace to a single blueprint line,
`docs/00-project/blueprint.md:49`, which reads:

> Test now GREEN after O-PARITY reconciliation: 129 keys kept, **860** English-verbatim
> placeholders tagged `// TODO(i18n): translate` (O-PLACEHOLDER), 7 previously-absent files
> created per locale, **847** orphan keys per locale flagged in a sidecar.

Git provenance shows that line is **older than the catalogue it describes**:

| Commit | Date | Change |
|---|---|---|
| `2372712` | 2026-10-14 10:07 | adds the blueprint, containing the 860 / 847 line |
| `0195c02` | 2026-10-16 17:59 | `#167: feat: add Spanish and Tagalog locale parity catalogues` — creates the real `lang/es/*` and `lang/tl/*` files |

The line was authored **two days before** commit `0195c02` created the catalogues, and 154
commits before the current tip. The blueprint prose also cited the sidecar evidence
directly:

> 847 orphan keys per locale flagged in a sidecar

That sidecar does not exist. `docs/01-issues/` contains only `2026-10-16-layout-audit.md`;
neither `docs/01-issues/i18n-parity-orphans-es.txt`, `...-tl.txt`, nor
`docs/01-issues/i18n-parity-backup/` is present, although the parity test's own docblock
(`tests/Unit/Lang/TranslationKeyParityTest.php:116`) still cites them as the authority.

Internal check on the stale line itself: `129 + 860 = 989`, but the canonical `en`
catalogue currently holds **995** entries. The blueprint figure is not even consistent
with the `en` set of its own era.

**Conclusion.** `860` and `847` are pre-catalogue planning estimates, never recomputed
against the committed files. `865` and `258` are the figures the documented rule produces
today from the canonical source locale.
